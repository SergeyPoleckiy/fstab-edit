# fstab-edit — руководство пользователя

## 1. Что такое fstab-edit

**fstab-edit** — утилита для безопасного редактирования `/etc/fstab` в Linux.
Она сочетает два интерфейса:

- **CLI** на Cobra — для автоматизации и скриптов (все команды работают
  неинтерактивно через `--yes` и machine-форматы `json`/`csv`/`tsv`);
- **TUI** на bubbletea — полноценный интерактивный редактор с таблицей
  записей, формами, автодополнением и экранами диагностики.

Ключевые свойства:

- **Транзакционная запись**: перед сохранением target повторно читается и
  сверяется по SHA-256 (контроль base hash), содержимое кандидата проверяется
  внутренним валидатором и `findmnt --verify`, запись выполняется атомарным
  rename с сохранением владельца, прав и xattrs.
- **Резервные копии и rollback**: перед каждой мутацией создаётся backup,
  при ошибке после записи выполняется ровно одна попытка автоматического
  отката.
- **Побайтовое сохранение**: lossless parser не нормализует документ —
  неизменённые строки, комментарии, порядок полей и отсутствие финального
  newline сохраняются.
- **Журналирование**: каждая мутирующая операция фиксируется в структурном
  JSON Lines-журнале с маскировкой секретов.

Программа — статический бинарник без внешних зависимостей во время работы
(кроме системных утилит, см. раздел 2).

## 2. Установка

### 2.1. Требования

- **Linux** — целевая платформа.
- **Go 1.22 или новее** и `make` — только для сборки из исходников.
- Опционально внешние утилиты util-linux (используются, если доступны):
  - `findmnt` — статическая проверка перед сохранением и команда
    `verify-mount`; без него сохранение блокируется (exit code 5);
  - `lsblk` — экран блочных устройств в TUI (клавиша `B`) и автодополнение
    поля «Устройство» в форме; при недоступности экран показывает ошибку,
    а автодополнение устройств просто не работает;
  - `blkid` — расширенные свойства устройств: доступен как внутренний API
    (`ProbeDevice`), но в production-потоках не вызывается; подстановка
    `UUID=`/`PARTUUID=`/`LABEL=`/`PARTLABEL=` в автодополнении идёт из вывода
    `lsblk`.

### 2.2. Сборка из исходников

```bash
git clone https://github.com/SergeyPoleckiy/fstab-edit.git
cd fstab-edit
make            # собирает ./fstab-edit
sudo make install    # сборка + установка бинаря и man-страницы
```

`make install` копирует статический бинарь в `$(PREFIX)/bin`
(`PREFIX` по умолчанию `/usr/local`, для другого пути —
`sudo make install PREFIX=/usr`) и man-страницу `fstab-edit(1)` (с gzip,
как принято в дистрибутивах) в `$(PREFIX)/share/man/man1`. После установки
полная справка по командам и кодам выхода доступна через `man fstab-edit`.
Для построения пакета или инспекции устанавливаемых файлов поддерживается
`DESTDIR` (например, `make install DESTDIR=/tmp/stage`); удаление —
`sudo make uninstall` (с теми же `PREFIX`/`DESTDIR`).

Версия подставляется автоматически из git (`git describe --tags`): сборка из
тега `v1.0` даёт версию `v1.0`, из коммитов после тега — `v1.0-N-g<хеш>`,
из нетегированного дерева — сокращённый хеш коммита. Ручной ввод версии не
поддерживается.

### 2.3. Установка готового бинарника

Из релизов проекта скачайте статический бинарник и скопируйте его в каталог
из `PATH`:

```bash
sudo cp fstab-edit /usr/local/bin/
sudo chmod 755 /usr/local/bin/fstab-edit
fstab-edit --version
```

Релизный архив содержит только бинарник; man-страница при такой установке
не ставится — полная справка по командам доступна в `docs/man/fstab-edit.1`
исходников (установка — `sudo make install`, см. §2.2) и на странице
релиза в репозитории проекта.

Удаление — просто удаление бинарника: программа не устанавливает
service-файлов и не меняет систему:

```bash
sudo rm /usr/local/bin/fstab-edit
```

## 3. Быстрый старт

```bash
# Посмотреть записи (только чтение, журнал не создаётся)
fstab-edit list

# Добавить запись: dry-run показывает diff без записи
fstab-edit add --device UUID=3f5c8a12-... --mount /mnt/data --type ext4 \
    --options defaults,noatime --dry-run

# То же самое по-настоящему: без TTY требуется --yes
fstab-edit add --device UUID=3f5c8a12-... --mount /mnt/data --type ext4 \
    --options defaults,noatime --yes

# Проверить документ без изменений
fstab-edit validate
fstab-edit verify-mount

# Открыть интерактивный редактор
fstab-edit tui        # или просто: fstab-edit
```

По умолчанию целевой файл — `/etc/fstab`; для экспериментов и chroot
используйте `--file=<path>`. Команды `list`, `validate`, `verify-mount` и
режим `--dry-run` ничего не пишут: ни target, ни журнал, ни backup.

## 4. CLI

### 4.1. Обзор команд

| Команда | Назначение |
|---------|-----------|
| `list` | Показывает активные и закомментированные записи |
| `add` | Добавляет новую запись |
| `edit` | Изменяет выбранные поля/comment |
| `delete` | Удаляет запись |
| `comment` | Комментирует активную запись |
| `uncomment` | Включает закомментированную запись |
| `validate` | Проверяет документ (`--offline` — только внутренний validator) |
| `verify-mount` | Статический `findmnt --verify` по фактическим байтам target |
| `backup` | Создаёт ручную копию без изменения target |
| `rollback` | Восстанавливает выбранную копию |
| `tui` | Открывает интерактивный TUI-редактор |

### 4.2. Глобальные (persistent) флаги

Применяются ко всем командам:

| Флаг | Значение по умолчанию | Описание |
|------|----------------------|----------|
| `--file <path>` | `/etc/fstab` | Путь к редактируемому fstab-файлу |
| `--dry-run` | `false` | Показать diff без записи, backup и lock |
| `--yes`, `-y` | `false` | Подтвердить допустимую операцию без prompt |
| `--output`, `-o` | `table` | Формат вывода: `table`, `json`, `csv`, `tsv` |
| `--log-level` | `info` | Уровень журнала: `debug`, `info`, `warn`, `error` |
| `--verbose`, `-v` | `false` | Дополнительная диагностика |
| `--quiet`, `-q` | `false` | Подавить обычный stdout (ошибки сохраняются) |
| `--backup-dir <path>` | каталог target | Каталог резервных копий |
| `--offline` | `false` | Отключить проверки внешних ресурсов |
| `--lang <ru|en>` | авто-резолв | Язык сообщений |
| `--config <path>` | не задан (авто-поиск, см. §6.2) | Путь к YAML-конфигурации |

Флаг применяется только при явном `--flag` (Cobra `Changed`): если флаг не
указан, значение берётся из env, YAML или default (см. раздел 6).

### 4.3. Селекторы записей

Команды `edit`, `delete`, `comment`, `uncomment` требуют селектор записи —
позиционный `<id>` либо ровно один из флагов. Позиционный `<id>` трактуется
так: число — номер физической строки записи, иное значение — mount point;
источник (source) позиционно не задаётся — только через `--device`:

| Флаг | Значение |
|------|----------|
| `--line <n>` | Номер физической строки записи (положительное число) |
| `--mount-point <path>` | Полное decoded значение mount point |
| `--device <source>` | Полное decoded значение источника записи |

Исходы выбора:

- Запись не найдена (ноль совпадений) — exit code **1** (validation).
- Некорректные аргументы (нечисловой или неположительный `--line` и т.п.) —
  exit code **2** (usage).
- Несколько совпадений (неоднозначный селектор) — exit code **8** со списком
  кандидатов. В интерактивном режиме (TTY и без `--yes`) CLI сначала печатает
  candidate lines в stderr и предлагает ввести номер одной из них: выбранная
  строка применяется, а некорректный номер, пустой ввод или EOF завершают
  команду тем же exit code **8** — произвольный кандидат никогда не выбирается
  автоматически. Вне TTY или с `--yes` chooser не вызывается: сразу exit
  code **8** со списком кандидатов.

### 4.4. `list`

Показывает активные и закомментированные записи target:

```bash
fstab-edit list
fstab-edit list -o json | jq .
fstab-edit list --file ./fstab.test
```

JSON-вывод имеет `schema_version: 1`. Обычные данные — stdout, диагностика —
stderr.

### 4.5. `add`

Добавляет новую запись. Обязательны `--device`, `--mount`, `--type`,
`--options`; `dump` и `pass` по умолчанию `0`.

| Флаг | Описание |
|------|----------|
| `--device <source>` | Источник записи: `UUID=...`, `LABEL=...`, `/dev/...` |
| `--mount <path>` | Точка монтирования |
| `--type <fs>` | Тип файловой системы: `ext4`, `xfs`, `btrfs`, `swap`, `nfs` и т.д. |
| `--options <list>` | Список опций монтирования через запятую |
| `--dump <n>` | Поле dump (по умолчанию `0`) |
| `--pass <n>` | Поле pass (по умолчанию `0`) |
| `--comment <text>` | Comment block перед записью |

```bash
fstab-edit add --device UUID=3f5c8a12-9d4e-4b7a-8c1f-2a6d9e0b4f55 \
    --mount /mnt/data --type ext4 --options defaults,noatime \
    --dump 0 --pass 2 --comment "Диск данных" --dry-run
```

### 4.6. `edit`

Изменяет выбранные поля записи. Требует селектор и хотя бы один изменяющий
флаг. Неуказанные поля не трогаются.

| Флаг | Описание |
|------|----------|
| `--line` / `--mount-point` | Селектор записи |
| `--device <source>` | Новое значение источника |
| `--mount <path>` | Новая точка монтирования |
| `--type <fs>` | Новый тип ФС |
| `--options <list>` | Новый список опций |
| `--dump <n>` / `--pass <n>` | Новые поля dump/pass |
| `--unset-dump` / `--unset-pass` | Удалить optional-поле dump/pass |
| `--comment <text>` | Заменить comment block записи |
| `--clear-comment` | Удалить comment block записи |

```bash
fstab-edit edit --mount-point /mnt/data --options defaults,noatime,nofail
fstab-edit edit --line 12 --clear-comment --dry-run
```

### 4.7. `delete`

Удаляет запись по селектору:

```bash
fstab-edit delete --mount-point /mnt/data --dry-run
fstab-edit delete --mount-point /mnt/data --yes
```

### 4.8. `comment` и `uncomment`

Комментирует активную запись или включает закомментированную. При
комментировании связанный comment block обрабатывается вместе с записью:

```bash
fstab-edit comment --line 12 --dry-run
fstab-edit uncomment --line 12 --yes
```

### 4.9. `validate`

Проверяет документ внутренним валидатором (поля, source/mount/FS type,
опции, duplicates, специальные предупреждения) и, без `--offline`, внешней
проверкой `findmnt --verify --tab-file` по приватному временному файлу.
`findmnt` ничего не монтирует — только статически проверяет кандидат.
Diagnostics объединяются в порядке internal → external:

```bash
fstab-edit validate
fstab-edit validate --offline --file ./fstab.test
```

Warnings допустимы и дают exit code 0; errors — exit code 1.

### 4.10. `verify-mount`

Выполняет только статический `findmnt --verify` по фактическим байтам target:

```bash
fstab-edit verify-mount
fstab-edit verify-mount --file ./fstab.test
```

### 4.11. `backup`

Создаёт ручную копию target без его изменения:

```bash
fstab-edit backup
fstab-edit backup --backup-dir /var/backups/fstab
fstab-edit backup --dry-run   # ничего не создаёт и target не читает
```

`--dry-run` выполняется до любого I/O: target не читается и копия не
создаётся, выводится structured результат с пустым `backup_id` и
`dry_run: true`.

### 4.12. `rollback`

Восстанавливает target из выбранной резервной копии. Выбор копии —
позиционный backup ID или `--restore=<id>` (по умолчанию — newest):

```bash
fstab-edit rollback --dry-run                        # read-only проход без записи
fstab-edit rollback                                  # newest, с подтверждением
fstab-edit rollback 2026-11-18_15-30-45.123456789Z   # конкретная копия
fstab-edit rollback --restore=2026-11-18_15-30-45.123456789Z --yes
```

`--dry-run` выполняет read-only проход: выбирает и проверяет копию, но не
создаёт safety backup и не пишет target; публикуется structured результат
(`selected_backup_id`, `dry_run: true`), diff при этом не печатается. В
интерактивном режиме без `--dry-run` diff выбранной копии против target
показывается в prompt подтверждения перед записью. Перед записью создаётся
safety backup текущего target. Копия развёртывается через доменный rollback с
проверками backup (hash, sidecar, владелец, mode).

### 4.13. Подтверждения, diff и вывод

- Подтверждение `[y/N]` (по умолчанию отказ) обязательно для мутаций и
  `rollback`. Без TTY требуется `--yes`. Формы ответа «да»: `д`, `да`, `y`,
  `yes`; любой иной ответ и пустая строка — отказ.
- `--yes` не обходит ошибки валидации, неоднозначность селектора и внешние
  сбои — только prompt.
- Интерактивный diff и warning-preview печатаются в stderr только в
  prompt-режиме; при `--yes` diff и diagnostics доступны в полях machine-JSON
  (`diff`, `diagnostics`).
- `--dry-run` показывает diff и diagnostics, ничего не меняя и не требуя
  `--yes`.
- Обычные данные — stdout (ровно один structured document для machine-
  форматов); диагностика, diff и prompts — stderr.

## 5. TUI

### 5.1. Запуск

```bash
fstab-edit tui        # или просто fstab-edit без аргументов
```

Требуется интерактивный терминал (TTY): без него команда завершается usage
error (exit code 2) с сообщением `tui.no_tty`. Запуск без аргументов
подменяется на `tui` только при пустом argv — `--help`, `--version` и
остальные команды работают как обычно. Мышь не поддерживается (только
клавиатура).

### 5.2. Главный экран — таблица записей

| Клавиша | Действие |
|---------|----------|
| `↑`/`↓`, `k`/`j` | Перемещение курсора |
| `Enter` | Редактировать запись под курсором |
| `Ins`, `i` | Добавить запись |
| `Del` | Удалить запись под курсором |
| `c` | Закомментировать/раскомментировать запись под курсором |
| `d` | Diff несохранённых изменений |
| `M`, `m` | Статус монтирований (findmnt) |
| `B`, `b` | Блочные устройства (lsblk) |
| `H`, `h` | История резервных копий |
| `L`, `l` | Журнал операций |
| `F1` или `?` | Помощь |
| `Ctrl+Z` | Отменить последнее действие (undo) |
| `F5` | Перезагрузить target (при несохранённых изменениях — подтверждение) |
| `Ctrl+S`, `F2` | Сохранить через transaction (backup → findmnt → atomic replace) |
| `q`, `Ctrl+Q`, `Ctrl+C`, `F10` | Выход (при несохранённых изменениях — подтверждение `[y/N]`, default No) |

Ошибки и предупреждения помечаются текстовыми маркерами (`!`, `?`) во всех
темах — интерфейс остаётся читаемым и в монохромном терминале.

### 5.3. Форма записи (Ins/Enter)

Поля: **Устройство** (source), **Точка монтирования**, **Тип ФС**,
**Опции**, **dump**, **pass**, а также comment block:

| Клавиша | Действие |
|---------|----------|
| `Tab` / `Shift+Tab`, `↓`/`↑` | Фокус по полям (по кругу) |
| `Enter` | Подтверждение: валидация → применение → таблица |
| `Esc` | Отмена, возврат в таблицу |
| `d` | Переключение панели diff-предпросмотра |
| `Ctrl+N` | Следующая подсказка автодополнения (подставить в поле) |
| `Ctrl+P` | Предыдущая подсказка автодополнения (подставить в поле) |

**Автодополнение.** Для полей «Устройство», «Тип ФС» и «Опции» под полями
показывается панель подсказок. Поля «Тип ФС» и «Опции» фильтруют варианты по
уже введённому префиксу; поле «Устройство» показывает все устройства без
префиксной фильтрации (значение вводится целиком):

- **Устройство** — список блочных устройств из `lsblk` (загружается при
  открытии формы). Подставляемое значение выбирается по приоритету (ТЗ v2
  этап 3): `UUID=<uuid>` — устойчиво к переименованию устройств, далее
  `PARTUUID=<partuuid>` — UUID раздела GPT, не зависящий от ФС, затем
  `LABEL=<метка>` и `PARTLABEL=<метка раздела>`; только при отсутствии всех
  четырёх — путь `/dev/...`. Правая колонка подсказки показывает тип, ФС,
  размер, точку монтирования и метку; если выбранный идентификатор встречается
  более чем у одного устройства (например, после клонирования диска), к
  колонке добавляется пометка «(не уникальный идентификатор)» — подстановка
  работает, но fstab может сослаться не на тот раздел. Если `lsblk`
  недоступен, форма работает как раньше — панель просто не показывается.
- **Тип ФС** — перечень поддерживаемых типов файловых систем.
- **Опции** — базовый перечень опций монтирования плюс добавки по типу ФС;
  бессмысленные сочетания (например, `discard` для сетевых ФС) исключаются.

Клавиши `Ctrl+N`/`Ctrl+P` листают варианты и подставляют выбранный в
активное поле; при пустой панели подсказок они ничего не делают.

### 5.4. Экран блочных устройств (`B`)

Плоская таблица вывода `lsblk`: `PATH`, `TYPE`, `FSTYPE`, `SIZE`,
`MOUNTPOINT`, `LABEL`, `UUID` (дерево устройств развёрнуто в список).
Данные загружаются при каждом входе на экран через тот же безопасный runner,
что и прочие проверки:

| Клавиша | Действие |
|---------|----------|
| `↑`/`↓`, `k`/`j` | Перемещение курсора |
| `PgUp`/`PgDown` | Прокрутка списка |
| `Esc` | Возврат в таблицу |

Пустой список — штатное состояние (отдельная подпись), ошибка загрузки
показывается текстом на экране и не блокирует выход по `Esc`.

### 5.5. Read-only экраны (монтирования, журнал)

Экран статуса монтирований (`M`) и журнала (`L`) поддерживают навигацию:

| Клавиша | Действие |
|---------|----------|
| `↑`/`↓`, `k`/`j` | Прокрутка |
| `PgUp`/`PgDown` | Страница вверх/вниз |
| `Esc` | Возврат в таблицу |

Экран помощи (`F1`/`?`) статический (весь список клавиш помещается
на одном экране) и закрывается только `Esc`.

### 5.6. Экран истории резервных копий (`H`)

| Клавиша | Действие |
|---------|----------|
| `↑`/`↓`, `k`/`j` | Выбор копии |
| `d` | Diff копии против target |
| `r` | Restore копии через доменный rollback (с safety backup) |
| `Esc` | Возврат в таблицу |

Сохранение (`Ctrl+S`/`F2`) и восстановление (`r`) в TUI идут через те же
transaction/rollback-механизмы, что и CLI: отдельной небезопасной реализации
записи в TUI нет. Недоступный журнал блокирует именно сохранение: журнал
открывается внутри транзакции.

### 5.7. Темы и язык

Тема оформления — `tui.theme` в конфигурации: `dark` (по умолчанию),
`light` (светлый фон), `high-contrast` (усиленная контрастность для
плохого зрения/проектора) или `monochrome` (без цвета, для базовых
терминалов). Неизвестное значение отклоняется ошибкой конфигурации.

Поверх любой встроенной темы (включая `monochrome`) действует
опциональный ключ `tui.colors` — пользовательская палитра:
переопределение цвета отдельных семантических ролей. Пример:

```yaml
tui:
  theme: dark
  colors:
    title: "#00ffff"   # hex #rrggbb
    selected_fg: "0"   # номер ANSI 0–255
    error: red         # имя ANSI-цвета
```

Допустимые форматы значения: hex `#rrggbb` (ровно шесть hex-цифр),
номер ANSI `0`–`255` или имя ANSI-цвета — восемь базовых (`black`, `red`,
`green`, `yellow`, `blue`, `magenta`, `cyan`, `white`) и восемь
bright-вариантов (`bright_black` … `bright_white`). Частичные форматы
(`#rgb`, `256`, `gray`) невалидны. Допустимые роли:

| Роль | Что окрашивает |
|------|----------------|
| `title` | Заголовки экранов |
| `header` | Шапка таблицы |
| `selected_fg` / `selected_bg` | Текст / фон выделенной строки |
| `muted` | Приглушённый текст (подсказки клавиш) |
| `info` | Информационный текст |
| `dirty` | Dirty-индикатор `*` в заголовке |
| `error` / `warning` | Семантические ошибка / предупреждение интерфейса |
| `field_source` | Поле «Устройство» записи (подсветка синтаксиса) |
| `field_mount` | Поле «Точка монтирования» |
| `field_fstype` | Поле «Тип ФС» |
| `field_options` | Поле «Опции» |

Переопределяется только цвет: атрибуты стилей (полужирный, faint,
подчёркивание, инверсия выделения) сохраняются, текстовые маркеры
(`!`, `?`) работают во всех темах. Неизвестная роль или невалидный
формат цвета отклоняются ошибкой конфигурации (exit code 2) с сообщением,
называющим отклонённую пару. Роли severity-диагностик валидатора
пользователю недоступны: их цвета зафиксированы ТЗ §5.3.

Язык интерфейса — общий резолв `--lang`/`FSTAB_EDIT_LANG`/локаль
(см. раздел 6).

### 5.8. Поведение при конфликтах и ошибках

- **Несохранённые изменения**: выход (`q` и др.) и перезагрузка (`F5`)
  запрашивают подтверждение `[y/N]` (default No).
- **Конфликт base hash**: если target изменился снаружи после загрузки,
  сохранение блокируется классом `conflict` (exit code 4 в CLI; в TUI —
  сообщение об ошибке, target остаётся старым).
- **Сбой findmnt**: сохранение блокируется (exit code 5 / сообщение `!` в
  TUI), target не трогается.
- **Ошибка после записи**: доменная transaction выполняет ровно одну попытку
  автоматического rollback из backup текущей операции; при успехе ошибка
  возвращается с `RolledBack=true`, при неудаче — критический exit code 7.
- **Undo (`Ctrl+Z`)** отменяет последнее действие в памяти; к уже сохранённым
  на диск изменениям undo не применяется.

## 6. Конфигурация (YAML)

### 6.1. Приоритеты настроек

Настройки резолвятся по приоритету: **CLI-флаги > `FSTAB_EDIT_*` env >
user YAML > system YAML > defaults**. CLI-флаг применяется только при явном
`--flag` (Cobra `Changed`), иначе значение берётся из нижележащего уровня.

### 6.2. Пути автоматической загрузки

- System: `/etc/fstab-edit/config.yaml` — обязан принадлежать root;
- User: `~/.config/fstab-edit/config.yaml` — не загружается автоматически
  для root-процесса (euid 0).
- `--config <path>` задаёт явный YAML вместо system/user; env всё равно выше
  его.

Security-checks: symlink-конфигурация отклоняется; файл не должен быть
group/others-writable (иначе exit code 3); system-config обязан принадлежать
root, user/explicit — effective UID. Некорректный YAML или значения — exit
code 2.

### 6.3. Переменные окружения

| Переменная | Настройка |
|------------|-----------|
| `FSTAB_EDIT_FILE` | Путь к target |
| `FSTAB_EDIT_BACKUP_DIR` | Каталог резервных копий |
| `FSTAB_EDIT_LOG_LEVEL` | Уровень журнала |
| `FSTAB_EDIT_LANG` | Язык (`ru`/`en`) |
| `FSTAB_EDIT_OUTPUT` | Формат вывода |

Неизвестные `FSTAB_EDIT_*` печатают `warning: ...` в stderr и игнорируются.

### 6.4. YAML-схема

| Ключ | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `fstab_path` | string | `/etc/fstab` | Целевой файл |
| `backup.dir` | string | каталог target | Каталог резервных копий |
| `backup.prefix` | string | `fstab.bak` | Префикс имён файлов копий |
| `backup.keep` | int | `10` | Сколько newest-копий сохраняет ротация |
| `log.file` | string | `/var/log/fstab-edit.log` | Файл журнала |
| `log.level` | string | `info` | Уровень журнала |
| `log.max_size_mb` | int | `10` | Порог ротации журнала, MiB |
| `log.keep` | int | `5` | Сколько архивов журнала хранить |
| `tui.theme` | string | `dark` | Тема TUI: `dark`, `light`, `high-contrast` или `monochrome` |
| `tui.colors` | map string→string | — | Переопределения цветов ролей палитры поверх `tui.theme` (см. §5.7) |

Язык и формат вывода из YAML не читаются (только env/CLI).

### 6.5. Пример конфигурации

```yaml
# /etc/fstab-edit/config.yaml
fstab_path: /etc/fstab

backup:
  dir: /var/backups/fstab
  prefix: fstab.bak
  keep: 10

log:
  file: /var/log/fstab-edit.log
  level: info
  max_size_mb: 10
  keep: 5

tui:
  theme: dark
  colors:
    title: "#00ffff"
    selected_fg: "0"
    error: red
```

## 7. Журнал операций

Файловый журнал — JSON Lines, по умолчанию `/var/log/fstab-edit.log`
(права `0600`). Один JSON-объект на строку:

| Поле | Описание |
|------|----------|
| `severity` | Уровень: `debug`, `info`, `warn`, `error` |
| `timestamp` | RFC 3339 UTC |
| `real_uid` / `effective_uid` | UID процесса |
| `sudo_user` / `sudo_uid` | Только при числовом `SUDO_UID` в окружении |
| `operation` | `add`, `edit`, `delete`, `comment`, `uncomment`, `backup`, `rollback` |
| `target` | Путь к редактируемому файлу |
| `backup_id` | ID backup операции (если создавался) |
| `result` | `success` / `error` / `cancelled` |
| `error_code` | Числовой код ошибки (при `error`) |
| `duration_ms` | Длительность операции |
| `old_value` / `new_value` | Изменённые строки diff (с redaction) |

Особенности:

- Журнал открывается **до** любой мутации: недоступный журнал блокирует
  изменение target кодом 3 (нет прав) или 6 (прочий I/O) — backup/lock/write
  не начинаются.
- Read-only команды (`list`, `validate`, `verify-mount`) и `--dry-run` файловый
  журнал не создают вовсе. TUI не открывает журнал при старте — только внутри
  транзакции сохранения.
- Сбой записи в журнал после успешного replace игнорируется и не мешает
  обязательному rollback.
- **Rotation**: при превышении `log.max_size_mb` (default 10 MiB) текущий файл
  уходит в `<file>.1`, архивы сдвигаются до `log.keep` (default 5).
- **Redaction**: `old_value`/`new_value` проходят маскировку секретов —
  `password=`, `credentials=`, `token=`, userinfo URL и др. заменяются на
  `***`.

## 8. Резервные копии и rollback

### 8.1. Как устроены копии

- Backup ID — ядро имени файла в UTC строго формата
  `YYYY-MM-DD_HH-MM-SS.nnnnnnnnnZ` (девять цифр nanoseconds и литеральный
  `Z`), например `2026-11-18_15-30-45.123456789Z`.
- Имена файлов: `<prefix>.<backup ID>` (данные) и `<prefix>.<backup ID>.json`
  (sidecar-метаданные). Default prefix — `fstab.bak`; каталог по умолчанию —
  каталог target.
- Sidecar (schema v1) — строгий JSON: `backup_id`, `created_at`,
  `source_path`, `source_sha256`, `backup_sha256`, `uid`, `gid`, `mode`,
  `operation` (`before-add`, `before-edit`, `before-delete`, `before-comment`,
  `before-uncomment`, `before-rollback`, `manual`), `program_version`,
  `source_verification` (`not_checked`, `valid`, `invalid`, `unavailable`).
- Backup создаётся из snapshot, повторно прочитанного под lock, файлы пишутся
  с mode `0600` через `O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC`, каждый файл
  fsync-ится и перечитывается для сверки SHA-256. Backup гарантирует
  побайтовое восстановление данных копии.

### 8.2. Автоматические и ручные копии

- Каждая мутация (`add`/`edit`/`delete`/`comment`/`uncomment`) и `rollback`
  создают backup текущего target **до** изменения (`before-*`).
- `fstab-edit backup` создаёт копию вручную (`operation: manual`), не меняя
  target.
- В TUI экран истории (`H`) показывает verified копии текущего target в
  порядке newest-first; `d` — diff копии против target, `r` — restore.

### 8.3. Ротация

После полностью успешной записи выполняется ротация: сохраняются `backup.keep`
(default 10) newest-копий; удаляются только собственные verified пары. Чужие,
повреждённые, symlink-записи каталога не входят в candidates и никогда не
удаляются. Backup текущей транзакции передаётся protected и переживает ротацию.

### 8.4. Восстановление

```bash
# Выбрать и проверить копию без записи (read-only проход, diff не печатается)
fstab-edit rollback --dry-run

# Новейшая копия, с интерактивным подтверждением (diff — в prompt подтверждения)
fstab-edit rollback

# Конкретная копия, без prompt
fstab-edit rollback --restore=2026-11-18_15-30-45.123456789Z --yes
```

Manual rollback: выбор копии через positional ID или `--restore` (по
умолчанию — newest), подтверждение обязательно (non-TTY требует `--yes`),
diff выбранной копии против target показывается в prompt подтверждения, перед
записью создаётся safety backup текущего target. Automatic rollback (внутри
транзакции) использует backup текущей операции напрямую.

## 9. Диагностика

### 9.1. Коды выхода

| Код | Значение |
|-----|----------|
| 0 | Успех (warnings допустимы) |
| 1 | Ошибки валидации |
| 2 | Usage error: неверные аргументы/флаги, некорректный конфиг |
| 3 | Недостаток прав: небезопасный config, недоступный журнал |
| 4 | Конфликт lock/base hash (target изменился снаружи) |
| 5 | Сбой внешней утилиты (findmnt, lsblk) |
| 6 | I/O: backup, запись, прочие файловые ошибки |
| 7 | Критический rollback: ошибка после записи, и откат не удался (наивысший приоритет) |
| 8 | Неоднозначный селектор записи |

### 9.2. Типичные ошибки и что делать

| Симптом | Причина | Решение |
|---------|---------|---------|
| `exit 3`, жалоба на config | Конфиг group/others-writable, symlink или чужой владелец | `chmod 600` на config; убрать symlink; исправить владельца |
| `exit 3`, недоступен журнал | `/var/log/fstab-edit.log` не пишется текущим пользователем | Запустить через sudo или задать `log.file` в доступное место |
| `exit 4` при сохранении | Target изменился другим процессом после загрузки | Перечитать (`F5` в TUI) и повторить правку |
| `exit 5` | `findmnt` не найден или завершился с ошибкой | Установить util-linux; проверить вывод `findmnt --version` |
| `exit 7` | Запись прошла, но post-check не удался, и rollback не восстановил | **Вручную** сверить target и backup из сообщения об ошибке; backup сохраняет пути recovery |
| `exit 8` | Селектор совпал с несколькими записями | Уточнить селектор (`--line`) или посмотреть список кандидатов в выводе |
| `tui.no_tty`, `exit 2` | TUI без интерактивного терминала | Запускать в TTY; в скриптах использовать CLI-команды с `--yes` |
| Warning про duplicates | Две записи с одинаковым mount point или source | Проверить `fstab-edit list`, удалить/отредактировать лишнее |

## 10. FAQ

**Требуется ли root?**
Для записи в `/etc/fstab` — да. Все проверки, `--dry-run`, `list`, `validate
--offline` и работа с `--file` в доступном месте работают без root.

**Что случится с моим fstab, если утилита упадёт посередине записи?**
Target заменяется атомарным rename: до успешного rename старый файл цел.
Если ошибка произошла после записи, transaction пытается восстановить backup
текущей операции ровно один раз; если и это не удалось — exit code 7 с путями
target и backup для ручного восстановления.

**Почему не использовать просто `echo >> /etc/fstab`?**
Прямая запись не проверяет синтаксис и семантику, не делает backup и не
сверяет, что файл не изменился снаружи. fstab-edit делает всё это
транзакционно и журналирует каждую операцию.

**Как безопасно поэкспериментировать?**
`fstab-edit --file ./fstab.test tui` или любая CLI-команда с `--file` и
`--dry-run`: ничего не пишется, журнал не создаётся.

**Чем отличаются `validate` и `verify-mount`?**
`validate` — внутренний валидатор плюс `findmnt --verify` (кандидат из
памяти); `verify-mount` — только статический `findmnt --verify` по фактическим
байтам target. Оба ничего не монтируют и не изменяют.

**Можно ли использовать fstab-edit в Ansible/скриптах?**
Да: машиночитаемые форматы `--output=json|csv|tsv` со `schema_version: 1`,
стабильные коды выхода, `--yes` для non-TTY, diff и diagnostics в полях JSON.

**Как убрать цвета в TUI?**
`tui.theme: monochrome` в конфиге (см. раздел 6). Ошибки и предупреждения
останутся помечены текстовыми маркерами `!` и `?`.

**Что делать, если `lsblk` не установлен?**
Программа работает полностью: экран `B` покажет ошибку загрузки, а
автодополнение устройств в форме просто не будет появляться. Остальные
функции не зависят от `lsblk`.
