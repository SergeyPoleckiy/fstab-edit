# TUI (этап 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Интерактивный TUI-интерфейс на bubbletea: таблица записей, формы добавления/редактирования, undo/dirty, транзакционное сохранение через ядро этапа 1, экраны diff/монтирований/истории/журнала/помощи, темы dark/monochrome, запуск командой `tui` и без аргументов.

**Architecture:** Пакет `tui/` (корень репозитория) реализует Model/Update/View bubbletea поверх существующего доменного слоя (`internal/parser`, `editor`, `validator`, `transaction`, `backup`, `sysutil`, `cliapp`). Сеансовое состояние (документ, стек undo, dirty) — в `tui/state.go`; все границы отказа (чтение target, transaction, backup, replace, findmnt, журнал) — за injectable-зависимостями `tui.Deps`, тесты используют fake seams и tempdir, без реального `/etc/fstab`. Темы и локализация — через `internal/i18n` (новый namespace `tui.*`) и `config.Settings.TUITheme`.

**Tech Stack:** Go 1.22 (toolchain 1.27), `github.com/chf13/cobra` уже есть; новые: `github.com/charmbracelet/bubbletea`, `github.com/charmbracelet/bubbles`, `github.com/charmbracelet/lipgloss` (production) и `github.com/charmbracelet/x/exp/teatest` (только тесты). Ядро этапа 1 не меняется, кроме точечных расширений, перечисленных в задачах.

## Global Constraints

- ТЗ §9.2 (дословно ключевое): изменения накапливаются в памяти до сохранения; `Ctrl+Z` отменяет несохранённое действие; `Ctrl+S` и `F2` запускают одну транзакцию сохранения; при конфликте версии TUI не перезаписывает файл и предлагает diff/повторную загрузку; `F5` при несохранённых изменениях запрашивает подтверждение; `Ctrl+Q`/`F10`/закрытие запрашивают подтверждение при несохранённых изменениях; после неуспешной проверки TUI показывает результат автоматического rollback и не предлагает оставить не прошедший проверку файл.
- ТЗ §9.3: только клавиатура (стрелки, Enter, Esc, Del, Tab); Ctrl+S/Ctrl+Q/Ctrl+Z, F1/F2/F5/F10.
- ТЗ §9.4: формы шести полей + связанный комментарий; проверка полей при вводе без изменения файла; предпросмотр итоговой строки и полного diff; ошибки не только цветом — текстовые обозначения.
- ТЗ §9.5 этап 2: экраны `M` (статус монтирований findmnt), `H` (история backup, diff, восстановление), `L` (журнал), `F1`/`?` (помощь).
- ТЗ §9.6 этап 2: темы `dark` (по умолчанию) и `monochrome`; текстовые признаки ошибок/предупреждений во всех темах.
- ТЗ п.71: фреймворк — bubbletea (выбрано владельцем проекта).
- ТЗ §16.2: TUI-тесты — `teatest`.
- ТЗ §14: журнал — перед сохранением проверяется доступность log; log недоступен до точки изменения → target не меняется; сбой log после replace не мешает rollback.
- Бизнес-логика не зависит от TUI: пакет `tui/` импортирует `internal/*`, обратных импортов нет.
- Все комментарии и строки интерфейса — через каталоги RU/EN (`internal/i18n`, namespace `tui.*`); коды операций/severity не локализуются.
- Тесты не читают и не пишут реальный `/etc/fstab`, `/var/log/fstab-edit.log`, системные пути — только `t.TempDir()` и fake `sysutil.CommandRunner`.
- Запуск без аргументов открывает TUI; `--help` всегда справку (ТЗ п.453). TUI без TTY — сообщение об ошибке и exit code 2, TUI не стартует.
- Каждая задача: `go test ./...`, `go vet ./...`, `golangci-lint run` чисто; коммит после задачи. Порядок: Task 1 → 7 последовательно.

## Общие типы (контракты между задачами)

```go
package tui

// Deps содержит границы отказа TUI; тесты подменяют их fake-реализациями.
// Зеркало cliapp.Dependencies плюс журнал: TUI не дублирует доменную логику,
// а получает те же seams, что и CLI.
type Deps struct {
    // ReadSnapshot безопасно читает target (байты + SHA-256 + canonical path).
    ReadSnapshot func(string) (writer.Snapshot, error)
    // ExecuteTransaction выполняет одну транзакцию сохранения candidate.
    ExecuteTransaction func(context.Context, transaction.Plan, transaction.Options) (transaction.TransactionResult, error)
    // ListBackups возвращает backups newest-first для истории.
    ListBackups func(target, prefix, directory string) ([]backup.Backup, error)
    // OpenBackup проверяет metadata/hash выбранной копии.
    OpenBackup func(string) (backup.Backup, error)
    // Replace атомарно заменяет target (восстановление из истории).
    Replace func(string, []byte) (writer.ReplaceResult, error)
    // VerifyTarget проверяет фактический target после restore.
    VerifyTarget func(context.Context, sysutil.CommandRunner, string) sysutil.Verification
    // OpenLog открывает журнал перед сохранением; ошибка блокирует сохранение.
    OpenLog func() (*logger.Logger, error)
}

// Screen перечисляет экраны приложения.
type Screen int

const (
    ScreenTable Screen = iota // главная таблица
    ScreenForm                // добавление/редактирование
    ScreenDiff                // просмотр diff
    ScreenSaveResult          // итог сохранения (вкл. rollback)
    ScreenConflict            // конфликт версии: diff + перезагрузка
    ScreenMounts              // статус монтирований (M)
    ScreenHistory             // история backup (H)
    ScreenLog                 // журнал (L)
    ScreenHelp                // помощь (F1/?)
)

// options — параметры запуска TUI (все уже резолвлены cmd-слоем).
type options struct {
    Target  string         // target fstab (default /etc/fstab, --file переопределяет)
    Lang    string         // резолвленный язык ru|en
    Theme   string         // tui.theme из config: "dark" (default) | "monochrome"
    Backup  backupSettings // dir/prefix/keep из config (пустой dir = каталог target)
    Log     logSettings    // file/level/max_size_mb/keep из config
    Runner  sysutil.CommandRunner // findmnt; тесты подменяют
    Deps    *Deps          // nil → ProductionDeps
}

type backupSettings struct{ Dir, Prefix string; Keep int }
type logSettings struct{ File, Level string; MaxSizeMB, Keep int }
```

Правило навигации (все экраны): `Esc` возвращает на главную таблицу; модальные подтверждения (выход с dirty, перезагрузка F5, восстановление) — `y/n`, default No.

```go
// Package tui содержит интерактивный интерфейс fstab-edit на bubbletea
// (этап 2 ТЗ). Пакет зависит от internal/* (прямой импорт), обратных
// зависимостей нет: бизнес-логика живёт в ядре, TUI — тонкий слой
// отображения и навигации.
package tui

import "github.com/charmbracelet/lipgloss"

// Theme — семантические стили приложения. Тема не задаёт шрифты глобально,
// а отдаёт стили по ролям; monochrome-вариант намеренно без цвета, потому
// что ТЗ §9.6 требует текстовые признаки ошибок во всех темах.
type Theme struct {
    Title    lipgloss.Style
    Header   lipgloss.Style
    Selected lipgloss.Style
    Error    lipgloss.Style
    Warning  lipgloss.Style
    Info     lipgloss.Style
    Muted    lipgloss.Style
    Dirty    lipgloss.Style
}

// LoadTheme возвращает тему по имени. Пустое и неизвестное имя дают dark
// (ТЗ §9.6: dark — тема по умолчанию на этапе 2).
func LoadTheme(name string) Theme {
    if name == "monochrome" {
        return Theme{
            Title:    lipgloss.NewStyle().Bold(true).Underline(true),
            Header:   lipgloss.NewStyle().Bold(true),
            Selected: lipgloss.NewStyle().Reverse(true),
            Error:    lipgloss.NewStyle().Bold(true),
            Warning:  lipgloss.NewStyle().Underline(true),
            Info:     lipgloss.NewStyle(),
            Muted:    lipgloss.NewStyle().Faint(true),
            Dirty:    lipgloss.NewStyle().Bold(true),
        }
    }
    return Theme{
        Title:    lipgloss.NewStyle().Bold(true).Foreground(lipgloss.Color("39")),
        Header:   lipgloss.NewStyle().Bold(true).Foreground(lipgloss.Color("244")),
        Selected: lipgloss.NewStyle().Foreground(lipgloss.Color("0")).Background(lipgloss.Color("39")),
        Error:    lipgloss.NewStyle().Foreground(lipgloss.Color("196")),
        Warning:  lipgloss.NewStyle().Foreground(lipgloss.Color("214")),
        Info:     lipgloss.NewStyle().Foreground(lipgloss.Color("255")),
        Muted:    lipgloss.NewStyle().Foreground(lipgloss.Color("240")),
        Dirty:    lipgloss.NewStyle().Foreground(lipgloss.Color("220")),
    }
}

// MarkError добавляет текстовый маркер ошибки "!": ТЗ §9.4 запрещает опираться
// только на цвет. Маркер ставится до стилизации, чтобы читаться без ANSI.
func (t Theme) MarkError(s string) string   { return t.Error.Render("! " + s) }
func (t Theme) MarkWarning(s string) string { return t.Warning.Render("? " + s) }
```

```go
// ProductionDeps заполняет границы отказа production-реализациями ядра.

    }
```

`tui/app.go` (скелет — полная модель с навигацией, таблица в table.go):

```go
package tui

import (
    tea "github.com/charmbracelet/bubbletea"

    "fstab-edit/internal/parser"
    "fstab-edit/internal/writer"
    "fstab-edit/pkg/models"
)

// model — bubbletea-модель TUI. Все поля unexported; тесты читают состояние
// через View() и ScreenNow().
type model struct {
    opts     options
    theme    Theme
    screen   Screen
    document *models.Document // nil при ошибке загрузки
    loadErr  error
    cursor   int // выбранная строка таблицы (индекс записи)
    status   string
}

// NewModel загружает target и собирает начальное состояние. Ошибка загрузки
// не паникует: показывается статусная строка с предложением F5.
func NewModel(opts options) tea.Model {
    m := model{opts: opts, theme: LoadTheme(opts.Theme), screen: ScreenTable}
    deps := opts.Deps
    if deps == nil {
        d := ProductionDeps(loggerOptions(opts))
        deps = &d
    }
    snapshot, err := deps.ReadSnapshot(opts.Target)
    if err != nil {
        m.loadErr = err
        return m
    }
    m.document = parser.Parse(snapshot.Data)
    return m
}

// loggerOptions собирает logger.Options из резолвленных настроек TUI.
func loggerOptions(opts options) logger.Options {
    return logger.Options{
        File: opts.Log.File, Level: logger.Severity(opts.Log.Level),
        MaxSizeMB: opts.Log.MaxSizeMB, Keep: opts.Log.Keep,
        RealUID: os.Getuid(), EffectiveUID: os.Geteuid(),
        SudoUser: sudoUser(), SudoUID: sudoUID(), // из env, числовой SUDO_UID
    }
}

// Init bubbletea: нет фоновых команд на старте.
func (m model) Init() tea.Cmd { return nil }

// Update обрабатывает сообщения. Навигация общая для всех экранов:
// Esc возвращает на таблицу, выход — с подтверждением при dirty (Task 3
// расширит confirmQuit; здесь — заглушка без dirty-логики).
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.KeyMsg:
        switch m.screen {
        case ScreenTable:
            return m.updateTable(msg)
        default:
            if msg.String() == "esc" {
                m.screen = ScreenTable
                return m, nil
            }
            return m, nil
        }
    }
    return m, nil
}

// View рендерит активный экран.
func (m model) View() string {
    if m.loadErr != nil {
        return Trf(m.opts.Lang, "load_error", m.opts.Target, m.loadErr.Error()) + "\n\n" +
            Tr(m.opts.Lang, "keys_help_hint") + "\n"
    }
    switch m.screen {
    case ScreenTable:
        return m.viewTable()
    default:
        return Tr(m.opts.Lang, "screen_placeholder")
    }
}

// ScreenNow возвращает активный экран (для тестов).
func (m model) ScreenNow() Screen { return m.screen }

// Run запускает bubbletea-программу. Вызывается из cmd-слоя.
func Run(opts options) error {
    _, err := tea.NewProgram(NewModel(opts), tea.WithAltScreen()).Run()
    return err
```

```go
package tui

import "fstab-edit/pkg/models"

// sessionState хранит несохранённые изменения сессии: исходные байты target,
// стек снапшотов для undo и признак dirty. ТЗ §9.2: изменения накапливаются
// в памяти до сохранения; undo работает до момента сохранения.
type sessionState struct {
    original  []byte
    undoStack [][]byte
    dirty     bool
}

// applyOp выполняет одну операцию над документом внутри сессии. Снапшот для
// undo фиксируется только если операция вернула nil: ошибка (недопустимый
// селектор/поля) не должна оставлять след в истории и не делает сессию dirty.
func (s *sessionState) applyOp(document *models.Document, op func(*models.Document) error) error {
    before := document.Serialize()
    if err := op(document); err != nil {
        return err
    }
    s.undoStack = append(s.undoStack, append([]byte(nil), before...))
    s.dirty = !bytes.Equal(before, document.Serialize())
    if !s.dirty && len(s.undoStack) > 0 {
        s.undoStack = s.undoStack[:len(s.undoStack)-1] // no-op не попадает в историю
    }
    return nil
}

// undo восстанавливает последний снапшот; false при пустом стеке. После
// восстановления dirty пересчитывается сравнением с original.
func (s *sessionState) undo(document *models.Document) bool {
    if len(s.undoStack) == 0 {
        return false
    }
    last := s.undoStack[len(s.undoStack)-1]
    s.undoStack = s.undoStack[:len(s.undoStack)-1]
    restored := parser.Parse(append([]byte(nil), last...))
    *document = *restored
    s.dirty = !bytes.Equal(document.Serialize(), s.original)
    return true
}

// candidate — сериализованные байты текущего документа для transaction.
func (s *sessionState) candidate(document *models.Document) []byte {
    return document.Serialize()
}
```

```go
package tui

import (
    "context"
    "errors"
    "time"

    "fstab-edit/internal/backup"
    "fstab-edit/internal/logger"
    "fstab-edit/internal/parser"
    "fstab-edit/internal/transaction"
)

// saveOutcome описывает итог одной попытки сохранения.
type saveOutcome struct {
    Result    transaction.TransactionResult
    Err       *transaction.TransactionError
    Conflict  bool
    LogOpened bool
}

// save выполняет транзакцию сохранения текущего документа. Порядок жёстко
// фиксирован ТЗ §9.2 и §14: журнал открывается до точки изменения; конфликт
// версии возвращается без перезаписи; сбой журнала после replace игнорируется
// (первичная ошибка и обязательный rollback важнее).
func save(ctx context.Context, m *model) saveOutcome {
    out := saveOutcome{}
    deps := m.deps()
    // Журнал: недоступность до mutation блокирует сохранение целиком.
    logFile, err := deps.OpenLog()
    if err != nil {
        out.Err = transactionFailureLike(err) // см. ниже: оборачиваем как несохранённый сбой
        return out
    }
    out.LogOpened = true
    defer logFile.Close()

    plan := transaction.Plan{
        TargetPath:      m.opts.Target,
        Candidate:       m.session.candidate(m.document),
        Operation:       backup.OperationBeforeEdit,
        BackupDirectory: m.opts.Backup.Dir,
        BackupPrefix:    m.opts.Backup.Prefix,
        RotationKeep:    m.opts.Backup.Keep,
    }
    txOptions := transaction.Options{
        Runner:           m.opts.Runner,
        BackupDirectory:  m.opts.Backup.Dir,
        BackupPrefix:     m.opts.Backup.Prefix,
        RotationKeep:     m.opts.Backup.Keep,
    }
    start := time.Now()
    result, txErr := deps.ExecuteTransaction(ctx, plan, txOptions)
    out.Result = result
    out.Err = txErr
    out.Conflict = txErr != nil && txErr.Kind == transaction.FailureConflict

    // Событие журнала: ошибка записи игнорируется — не заменяет первичную
    // ошибку и не мешает rollback (ТЗ §14).
    severity := logger.SeverityInfo
    resultCode := logger.ResultSuccess
    errorCode := 0
    if txErr != nil {
        severity = logger.SeverityError
        resultCode = logger.ResultError
        errorCode = 4 // ExitConflict и прочие сбои транзакции маппятся в cmd; для журнала достаточно кода сбоя
        if !out.Conflict {
            errorCode = 6
        }
    }
    _ = logFile.Log(logger.Event{
        Severity: severity, Operation: logger.OperationEdit, Target: m.opts.Target,
        BackupID: result.Backup.ID, Result: resultCode, ErrorCode: errorCode,
        DurationMs: time.Since(start).Milliseconds(),
        OldValue: logger.Redact(string(m.session.original)),
        NewValue: logger.Redact(string(m.session.candidate(m.document))),
    })

    if txErr == nil {
        // Сохранение успешно: сессия сбрасывается, original обновляется.
        m.session.original = m.session.candidate(m.document)
        m.session.undoStack = m.session.undoStack[:0]
        m.session.dirty = false
    }
    return out
}
```

Для случая недоступного журнала: `transactionFailureLike` строит `*transaction.TransactionError{Kind: transaction.FailureIO, ...}` с русским текстом (см. `internal/transaction.transactionFailure` — он неэкспортируемый, поэтому конструируем структуру напрямую; поля `Kind`, `Sentinel`, `Description` — сверь по transaction.go и заполни минимально). Показ ошибки в UI — через ScreenSaveResult (Task 3 же): реализуй в `viewSaveResult` вывод: успех (backup ID, результат проверки), ошибка — `! <описание>` + при `RolledBack` строку «автоматический rollback выполнен, target восстановлен», при `RollbackError` — `!` + причину (recovery paths из `result.Recovery`). После неуспешной проверки НЕ предлагать «оставить файл» (ТЗ §9.2): единственное действие — Esc.

```go
package tui

import (
    "bufio"
    "context"
    "encoding/json"
    "os"
    "strings"

    "fstab-edit/internal/diff"
    "fstab-edit/internal/logger"
    "fstab-edit/internal/sysutil"
    "fstab-edit/pkg/models"
)

// newDiffModel разбивает unified diff на строки для постраничного показа.
func newDiffModel(d string) diffModel { return diffModel{lines: strings.Split(d, "\n")} }

// scroll сдвигает окно просмотра; границы зажаты, отрицательный offset недопустим.
func (d *diffModel) scroll(delta int) {
    max := len(d.lines) - 1
    if max < 0 { max = 0 }
    d.offset += delta
    if d.offset < 0 { d.offset = 0 }
    if d.offset > max { d.offset = max }
}

// loadMounts собирает статус монтирований: verify current candidate через
// findmnt и per-entry проверку смонтированности. Сбои findmnt не паникуют и
// не маскируются: попадают в Err отдельно от пустого списка (ТЗ §9.5).
func loadMounts(ctx context.Context, m *model) mountsModel {
    out := mountsModel{Mounted: make(map[int]bool)}
    verification := sysutil.VerifyCandidate(ctx, m.opts.Runner, m.session.candidate(m.document))
    out.Verification = verification
    if verification.Execution.Err != nil {
        out.Err = verification.Execution.Err
        return out
    }
    for _, idx := range m.entryIndexes() {
        node := m.document.Nodes[idx]
        if node.Entry == nil || node.Kind != models.NodeEntry { continue }
        mount := node.Entry.MountPoint.Value
        res := m.opts.Runner.Run(ctx, "findmnt", "--noheadings", "--output=TARGET", mount)
        out.Mounted[idx+1] = res.ExitCode == 0
    }
    return out
}

// loggerEvent — строка журнала; timestamp строкой для отображения без time.Parse.
type loggerEvent struct {
    Severity  string `json:"severity"`
    Timestamp string `json:"timestamp"`
    Operation string `json:"operation"`
    Target    string `json:"target"`
    BackupID  string `json:"backup_id,omitempty"`
    Result    string `json:"result"`
}

// loadLog читает последние limit событий журнала newest-last. Файл только
// читается: read-only экран не создаёт журнал (ТЗ §14).
func loadLog(m *model, limit int) logModel {
    out := logModel{}
    f, err := os.Open(m.opts.Log.File)
    if err != nil { out.Err = err; return out }
    defer f.Close()
    lines := make([]string, 0)
    scanner := bufio.NewScanner(f)
    for scanner.Scan() { lines = append(lines, scanner.Text()) }
    if err := scanner.Err(); err != nil { out.Err = err; return out }
    if len(lines) > limit { lines = lines[len(lines)-limit:] }
    out.Events = make([]loggerEvent, 0, len(lines))
    for _, line := range lines {
        var e loggerEvent
        if err := json.Unmarshal([]byte(line), &e); err != nil { continue } // битая строка пропускается
        out.Events = append(out.Events, e)
    }
    return out
}

// diffSession строит unified diff original→current candidate для экрана diff.
func (m model) diffSession() string {
    return diff.Unified("<original>", "<current>", m.session.original, m.session.candidate(m.document))
}
```

```go
package tui

import (
    "context"

    "fstab-edit/internal/backup"
    "fstab-edit/internal/cliapp"
    "fstab-edit/internal/transaction"
)

// loadHistory читает список backups через seam; сортировку newest-first
// выполняет backup.List.
func loadHistory(m *model) historyModel {
    out := historyModel{}
    backups, err := m.deps().ListBackups(m.opts.Target, m.opts.Backup.Prefix, m.opts.Backup.Dir)
    if err != nil { out.Err = err; return out }
    out.Backups = backups
    return out
}

func (h historyModel) Selected() backup.Backup { return h.Backups[h.Cursor] }

// restoreSelected восстанавливает target из выбранной копии через доменный
// сервис: selection уже сделана, поэтому RestoreID — точный ID копии; safety
// backup, replace и post-verify выполняет cliapp.Service.Rollback без
// отдельной небезопасной реализации записи (критерий завершения этапа 2).
func restoreSelected(ctx context.Context, m *model, b backup.Backup) restoreResult {
    service := cliapp.NewService(cliappDepsFromTui(m), m.opts.Runner)
    result, exitErr := service.Rollback(ctx, m.opts.Target, cliapp.RollbackRequest{
        RestoreID: b.ID,
        Directory: m.opts.Backup.Dir,
        Prefix:    m.opts.Backup.Prefix,
    })
    out := restoreResult{Result: result, Err: exitErr}
    if exitErr == nil {
        // После restore на диске другие байты: перечитываем сессию из target.
        m.reloadFromDisk()
    }
    return out
}

// cliappDepsFromTui адаптирует tui.Deps к cliapp.Dependencies (поля 1:1).
func cliappDepsFromTui(m *model) cliapp.Dependencies {
    d := m.deps()
    return cliapp.Dependencies{
        ReadSnapshot: d.ReadSnapshot, ExecuteTransaction: d.ExecuteTransaction,
        CreateBackup: productionCreateBackup, // backup.Create (прямая ссылка)
        SelectBackup: productionSelectBackup, // backup.Select
        OpenBackup:   d.OpenBackup, Replace: d.Replace, VerifyTarget: d.VerifyTarget,
    }
}
```

(Сигнатуры `productionCreateBackup`/`productionSelectBackup` — прямые ссылки `backup.Create` и `backup.Select`; если lint требует прямого использования, встройте литералы функций.)
