Общие сведения

1.1. Назначение программы

fstab-edit — утилита для безопасного и удобного редактирования файла /etc/fstab в Linux. Программа предоставляет два интерфейса: CLI (для автоматизации и скриптинга) и TUI (псевдографический интерактивный режим), обеспечивает валидацию вносимых изменений, автоматическое резервное копирование и механизм отката.

1.2. Основания для разработки

Файл /etc/fstab является критически важным системным конфигурационным файлом Linux. Согласно официальной документации (man fstab), некорректное содержимое этого файла может привести к невозможности загрузки системы. Ручное редактирование без средств валидации сопряжено с высокими рисками, а существующие решения либо слишком примитивны (текстовые редакторы), либо входят в состав тяжеловесных графических утилит.

1.3. Цели разработки

Минимизация риска повреждения системы при редактировании /etc/fstab.
Упрощение добавления/редактирования записей для пользователей любого уровня подготовки.
Обеспечение возможности автоматизации операций в скриптах.
Предоставление единого инструмента с CLI и TUI интерфейсами.

Требования к программе

2.1. Функциональные требования

Программа должна поддерживать следующие операции:

| № | Операция | Описание |
|---|----------|----------|
| 1 | Просмотр | Вывод всех записей /etc/fstab в форматированном виде (таблица) |
| 2 | Добавление | Добавление новой записи с валидацией всех полей |
| 3 | Редактирование | Изменение любого из 6 полей существующей записи |
| 4 | Удаление | Удаление указанной записи |
| 5 | Комментирование/раскомментирование | Временное отключение записи без удаления (префикс #) |
| 6 | Валидация | Проверка синтаксиса файла, существования устройств, корректности опций |
| 7 | Проверка монтирования | Запуск mount -a / findmnt --verify перед сохранением |
| 8 | Резервное копирование | Автоматическое создание резервной копии перед изменениями |
| 9 | Откат изменений | Восстановление из резервной копии |
| 10 | Автоподстановка UUID/LABEL | Получение UUID/LABEL через blkid при добавлении записи |
| 11 | Сохранение комментариев | Полная поддержка комментариев, включая редактирование |

2.2. Требования к интерфейсу

Программа реализуется в гибридном варианте: CLI (Command Line Interface) для скриптинга и автоматизации + TUI (Text User Interface) для интерактивной работы.

CLI-интерфейс

4.1. Структура команд

Используется классический стиль subcommands:

fstab-edit list                       # Просмотр записей
fstab-edit add [флаги]                # Добавление записи
fstab-edit edit <id> [флаги]          # Редактирование
fstab-edit delete <id>                # Удаление
fstab-edit comment <id>               # Закомментировать
fstab-edit uncomment <id>             # Раскомментировать
fstab-edit validate                   # Валидация файла
fstab-edit verify-mount               # Проверка монтирования
fstab-edit backup                     # Создание резервной копии вручную
fstab-edit rollback [--restore=<ts>]  # Откат изменений
fstab-edit tui                        # Запуск TUI-режима

4.2. Запуск TUI

Команда fstab-edit tui — явный запуск.
Запуск без аргументов (fstab-edit) — автоматический переход в TUI-режим.

4.3. Идентификация записей

Идентификатор записи (<id>) в командах edit, delete, comment, uncomment может быть указан в одном из форматов:

Номер строки: 3
Точка монтирования: /mnt/data
Устройство: UUID=abc-123, /dev/sda1 и т. п.

Программа автоматически определяет тип идентификатора. При неоднозначности — интерактивный выбор из подходящих записей.

4.4. Глобальные флаги

| Флаг | Назначение |
|------|------------|
| --file=<path> | Альтернативный путь к fstab (для chroot, контейнеров, тестирования) |
| --dry-run | Показать изменения без применения |
| --yes, -y | Автоподтверждение всех запросов (для скриптов) |
| --output=<format>, -o | Формат вывода: table (по умолчанию), json, csv, tsv |
| --log-level=<level> | Уровень логирования: debug, info, warn, error |
| --verbose, -v | Детальный вывод |
| --quiet, -q | Подавление вывода |
| --backup-dir=<path> | Переопределение директории для резервных копий |
| --help, -h | Справка |
| --version | Версия программы |

4.5. Примеры использования
bash
Просмотр всех записей в виде таблицы
fstab-edit list

Просмотр в JSON
fstab-edit list -o json

Добавление записи с автоподстановкой UUID
fstab-edit add --device /dev/sdb1 --mount /mnt/data --type ext4 \
               --options defaults,noatime --dump 0 --pass 2

Редактирование опций существующей записи
fstab-edit edit /mnt/data --options defaults,noatime,nofail

Удаление записи с автоподтверждением
fstab-edit delete /mnt/data --yes

Откат к последней резервной копии
fstab-edit rollback

Откат к конкретной копии
fstab-edit rollback --restore=2026-04-21_15-30-45

Функциональные клавиши: F1 (помощь), F2 (сохранить), F5 (обновить), F10 (выход).

Модальная форма добавления/редактирования с валидацией в реальном времени.
Выпадающие списки для выбора типа ФС из поддерживаемого перечня.
Выбор устройства из списка доступных блочных устройств (получение данных через lsblk / blkid).
Автодополнение опций монтирования (контекстно-зависимое, с учётом типа ФС).
Предпросмотр итоговой строки fstab перед сохранением.
Подсветка синтаксиса (разные цвета для разных полей записи).
Подсветка ошибок и предупреждений (красный — ошибка, жёлтый — предупреждение).

Работа с полями fstab

6.1. Поле 1 — Устройство

Поддерживаемые форматы идентификации устройства:

UUID=xxxx-xxxx
LABEL=mylabel
PARTUUID=xxxx-xxxx
PARTLABEL=mylabel
Прямые пути: /dev/sda1, /dev/nvme0n1p1, /dev/mapper/vg-lv
Сетевые ресурсы: //server/share (CIFS), server:/path (NFS)
Псевдо-ФС: tmpfs, proc, sysfs, none

6.2. Поле 3 — Тип файловой системы

Полный список поддерживаемых типов с валидацией:

Локальные: ext2, ext3, ext4, xfs, btrfs, f2fs, reiserfs
Windows-совместимые: ntfs, ntfs-3g, vfat, exfat, msdos
Оптические/съёмные: iso9660, udf
Сетевые: nfs, nfs4, cifs, smbfs, sshfs
Псевдо-ФС: tmpfs, proc, sysfs, devpts, swap
Специальные: overlay, bind, auto

6.3. Поле 4 — Опции монтирования

Строгая валидация в зависимости от типа ФС (например, discard применим не ко всем ФС).
Автодополнение и подсказки популярных опций: defaults, noatime, nofail, ro, rw, user, auto, noauto, exec, noexec, sync, async, relatime, nodev, nosuid и др.
Проверка отсутствия пробелов и корректности разделителей.

6.4. Поля 5, 6 — Dump и Pass

Строгая проверка:
dump ∈ {0, 1}
pass ∈ {0, 1, 2}

При вводе некорректных значений — отказ в сохранении.

6.5. Комментарии

Полная поддержка сохранения существующих комментариев.
Возможность добавлять и редактировать комментарии, привязанные к записям.
Сохранение порядка строк и форматирования файла.

Резервное копирование и откат

7.1. Создание резервных копий

| Параметр | Значение |
|----------|----------|
| Место хранения | По умолчанию: рядом с оригиналом — /etc/fstab.bak.<timestamp> |
| Переопределение | Через флаг --backup-dir=<path> или параметр backup_dir в конфиге |
| Формат timestamp | YYYY-MM-DD_HH-MM-SS (например, fstab.bak.2026-04-21_15-30-45) |
| Момент создания | Только при явном сохранении изменений (перед записью в /etc/fstab) |
| Ротация | Хранить последние 10 копий, старые удалять автоматически |

7.2. Откат изменений

Команда fstab-edit rollback — откат к последней резервной копии.
Флаг --restore=<timestamp> — откат к конкретной копии по идентификатору.
В TUI — отдельный экран с интерактивным выбором копии и просмотром diff.
При откате старый файл также сохраняется как резервная копия (чтобы откат можно было отменить).

Логирование и обработка ошибок

8.1. Логирование

| Параметр | Значение |
|----------|----------|
| Назначение | Отдельный лог-файл (в systemd journal не пишется) |
| Путь | Задаётся в конфигурационном файле (по умолчанию /var/log/fstab-edit.log) |
| Уровни | DEBUG, INFO, WARN, ERROR; уровень задаётся через флаг --log-level или конфиг |
| Флаги | --verbose / -v — детальный вывод, --quiet / -q — подавление |

8.2. Формат записи лога

Каждая запись должна содержать:
Timestamp (ISO 8601, например, 2026-04-21T15:30:45+03:00)
Уровень (INFO, WARN, ERROR, DEBUG)
Пользователь (real UID, effective UID, информация о sudo — через SUDO_USER)
Операция (add, edit, delete, comment, rollback и т. д.)
Старое значение (для операций изменения)
Новое значение (для операций изменения)

Пример:

2026-04-21T15:30:45+03:00 INFO user=admin(sudo:root) operation=edit \
  old="UUID=abc / ext4 defaults 0 1" \
  new="UUID=abc / ext4 defaults,noatime 0 1"

8.3. Обработка критических ошибок

Если после сохранения mount -a / findmnt --verify обнаруживает проблему:

В CLI-режиме: автоматический откат из последнего бэкапа с уведомлением пользователя.
В TUI-режиме: интерактивный диалог с выбором — откатить или оставить изменения (с подробным описанием проблемы).

8.4. Подтверждения операций

Подтверждение ([y/N]) требуется для всех операций изменения: add, edit, delete, comment, uncomment, rollback.
Флаг --yes / -y — автоматическое подтверждение (для использования в скриптах).

Конфигурация

9.1. Источники конфигурации (в порядке приоритета)

Флаги командной строки — наивысший приоритет.
Переменные окружения (префикс FSTAB_EDIT_, например, FSTAB_EDIT_LOG_LEVEL).
Конфигурационный файл — низший приоритет.

9.2. Конфигурационный файл

Путь: ~/.config/fstab-edit/config.yaml (пользовательский) или /etc/fstab-edit/config.yaml (системный).
Формат: YAML.

Пример:
yaml
Путь к альтернативному fstab (по умолчанию /etc/fstab)
fstab_path: /etc/fstab

Настройки резервного копирования
backup:
  dir: /etc                 # каталог для резервных копий
  prefix: fstab.bak         # префикс имени файла
  keep: 10                  # количество хранимых копий

Логирование
log:
  file: /var/log/fstab-edit.log
  level: info               # debug, info, warn, error

TUI
tui:
  theme: dark               # dark, light, high-contrast, monochrome
